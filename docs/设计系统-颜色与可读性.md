# 设计系统 · 颜色与可读性 · 2026-11-07

> 这份文档记录的是**规则**，不是配色方案。
> 配色在 `app/design-system.css` 里；这里写的是「为什么会有看不见的字」，
> 以及**怎么在写完代码之后才发现它**。

---

## 一、两种「看不见」，只有一种是 bug

| 情况 | 例子 | 是不是 bug |
|---|---|---|
| **颜色 == 背景色** | 数字 `#0b0f12` 压在 `#0b0f12` 上 | **是 bug**，完全看不见 |
| 颜色偏暗但可辨 | `#5a666e` 压在 `#0b0f12` 上 | 是设计决定，不是 bug |

**判据是「相等」，不是「对比度低」。** WCAG 那套比值是给无障碍评审用的，
这里管的是「有没有字直接消失了」。

2026-11-07 之前，全站有 **48 处**比值 1.0 的隐形字、19 处 1.31 的近隐形字。
现在：**全站无低于 1.50 的文字**。

## 二、三条会让人写出隐形字的规则

### 1. 一个没被定义的类，不是警告，是**空操作**

```jsx
<p className="text-v2-accent-400">Shenhe Zhongke</p>
```

`text-v2-accent-400` **在样式表里不存在**（accent 只有 800/700/600/500/300/100/050），
所以这条 class 什么也没做 —— 元素保留**它继承来的颜色**。

后果：后台登录页那行字继承了 body 的前景色 `#1f2a2e`，压在 `#0b0f12` 上，
**比值 1.31，读不出来**。10 个后台页面都中招，而且**没有任何东西会报错**。

> **规则**：颜色类要么在样式表里存在，要么就别写。
> **闸门**：`python scripts/check_colour_classes_exist.py`
> —— 源码里用到的每个颜色类，都必须在**构建产物的 CSS** 里存在。

### 2. 深色底上的组件，要问它要深色调

```jsx
<DataBar items={standardDataBar(['park', 'capacity', 'skus', 'labs'])} />
```

`DataBar` 有 `tone` prop（`'light'` 默认 / `'dark'`）。这个页面在
`bg-v2-ink-900` 的区块里，却没传 `tone="dark"` —— 于是数字被画成
`text-v2-ink-900`，**和底色一模一样**。

> **规则**：深色区块里的组件，必须传深色调。
> **闸门**：`scripts/check_text_contrast.mjs` 会量出来。

### 3. 渐变和图片**不是颜色**

`.v3-band-dark` 的背景是 `linear-gradient(...)`，所以它的 `backgroundColor`
是透明的。顺着往上找背景，会一路找到页面的白色 body ——
于是「白字压深色渐变」被误判成「白字压白底」。

> **规则**：背景读不出来的时候，**不报**。闸门对渐变/图片背景一律跳过。
> 这不是偷懒：报 48 处假缺陷的闸门，下次就没人读了。

## 三、怎么量（而不是靠眼睛）

### 闸门：`scripts/check_text_contrast.mjs`

```bash
node scripts/check_text_contrast.mjs                 # 全部 94 页
node scripts/check_text_contrast.mjs --only products.html
node scripts/check_text_contrast.mjs --distribution  # 打印全站对比度分布
```

它**问浏览器**：每段文字实际被画成什么颜色、背后是什么颜色。
读源码不够 —— 背景可能来自祖先、alpha 可能洗淡颜色、工具类可能输掉层叠，
**只有渲染后的页面知道**。

### 阈值是量出来的

```
< 1.05   0        ← 隐形（颜色 == 背景）
< 1.30   0
< 1.50   0        ← 修复后全站无低于此的
< 1.80   0
< 2.00   73       ← 面包屑分隔符「/」这类装饰
```

阈值取 **1.5**：能抓住真实的三类缺陷（1.0 / 1.31 / 1.58），
又不会把装饰性的分隔符算进来。

### 它怎么跟浏览器说话

**CDP 管道传输**（`--remote-debugging-pipe`，消息走 fd 3/4、`\0` 分隔）。

⚠️ **不要用 WebSocket，也不要用 `--dump-dom`**：
Chrome 156 的新 headless 在 `--dump-dom` 时会**脱离进程**，stdout 0 字节；
而 Node 内置的 WebSocket 在进程结束时会触发 libuv 断言
（`Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)`），
把**通过**也变成失败。管道传输两个问题都没有。

### 证明闸门会红

```bash
python scripts/check_text_contrast_gate_fails.py
```

它把构建产物里的颜色类改回坏值 → 闸门必须报出
`ratio 1, rgb(11,15,18) on rgb(11,15,18) "30,000 m²"` → 还原 → 必须复绿。

**一个只绿过的闸门不是闸门。**

## 四、颜色类清单在哪

| | 位置 |
|---|---|
| token（`--v2-ink-900` 等） | `app/design-system.css` 顶部的 `:root` |
| 由 token 生成的类（`.text-v2-ink-900` 等） | `app/design-system.css` 的「backgrounds / text colour / borders」三段 |
| 真正生效的那份 CSS | 构建产物 `out/_next/static/chunks/*.css` |

**改配色时改 token，别改类** —— 类是由 token 生成的。
新增一个档位要同时做两件事：加 token、加类；否则 `check_colour_classes_exist.py` 会红。
